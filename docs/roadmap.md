## News AI Trading Roadmap

### 1. 실제 AI 뉴스 분석 검증

- `OPENAI_API_KEY` 설정
- 사용할 모델과 일일 분석 건수 결정
- 실제 뉴스로 요약, 감성, 중요도, 관련 종목 정확도 확인
- API 비용과 처리 시간 기록

### 2. 뉴스와 국내 종목 연결

- AI가 반환한 회사명을 `data/stocks.json`의 정확한 종목코드로 매핑
- 동명이인, 계열사, 우선주 구분
- 확실하지 않은 결과는 매매 후보에서 제외
- 종목별 관련 뉴스 묶음 제공

### 3. 중복 사건 통합

- 같은 사건을 다룬 여러 기사를 하나의 뉴스 이벤트로 통합
- 단순 기사 개수가 매매 신뢰도를 부풀리지 않도록 방지
- 출처 수와 신뢰도를 별도로 계산

### 4. 종목별 일일 AI 전망 생성

- 여러 뉴스 분석 결과를 종목별로 종합
- 매수 후보, 매도 후보, 관망 생성
- 신뢰도, 예상 영향 기간, 주요 근거 기록
- 이 단계에서는 아직 주문하지 않음

### 5. 가격·거래량 데이터 결합

- 현재가, 전일 대비, 거래량, 변동성을 AI 전망과 결합
- 뉴스만 긍정적이고 가격이 과열된 경우 주문 차단
- 뉴스 신호의 유효기간이 지나면 자동 폐기

### 6. AI 후보 종목 자동 발굴

- 사용자가 등록한 관심종목에만 의존하지 않도록 변경
- 뉴스에서 발견한 종목을 자동 감시 후보에 추가
- 거래정지, 관리종목, 유동성 부족 종목 제외
- 실제 관심종목과 AI 후보군을 화면에서 구분

### 7. 뉴스 기반 모의매매 결정 엔진

- AI 전망과 가격 조건을 이용해 매수, 매도, 관망 결정
- AI가 주문 수량도 예산 범위에서 제안
- 기존 위험관리 엔진이 마지막으로 주문 승인
- 모든 결정에 사용된 뉴스와 근거 저장

### 8. 성과 추적

- AI 판단 시점 가격과 이후 가격 비교
- 1일, 3일, 5일 후 수익률 측정
- 감성 분석 적중률, 종목별 성과, 최대 낙폭 집계
- 성과가 나쁜 신호는 자동매매에서 제외

### 9. 대시보드 확장

- 종목별 뉴스 타임라인
- AI 분석 상세 근거
- 오늘의 후보 종목
- 모의 주문 여부와 차단 사유
- API 사용량과 예상 비용
- 뉴스 DB 용량 및 정리 기록

### 10. 운영 안정화

- 뉴스 제공처 장애 시 재시도
- AI 응답 오류와 타임아웃 처리
- 일일 API 비용 제한
- SQLite 백업 및 복구
- 서비스 재시작 후 미완료 분석 복구

### 11. 라즈베리파이 배포 준비

- 로컬에서 전체 흐름을 충분히 검증
- ARM 기기에서 직접 빌드하지 않고 로컬 또는 CI에서 이미지 생성
- 라즈베리파이는 완성된 Docker 이미지만 내려받아 실행
- CPU, 메모리, 온도, 저장공간 제한 설정
